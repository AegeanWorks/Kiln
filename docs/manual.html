Kiln manual

Kiln forges reproducible JSON and CSV test fixtures from a typed schema and a seed. This page is a local, self-contained copy of the command reference; the README is the canonical quick start.

Schema

version = 1
seed = 20261122
count = 4
format = json

record User {
  id: int(1..9999)
  name: enum(Alice, Bob, Cara, Deniz)
  active: bool
  score: float(0..10000)
  handle: string("u_", 3..6)
  tags: list(enum(red, green, blue), 0..3)
}

Commands

  • kiln generate <schema> [--format json|jsonl|csv] [--count N] [--out FILE] [--edges] [--seed N] (schema '-' reads stdin)
  • kiln check <schema> --fixture <FILE>
  • kiln check --manifest kiln.toml
  • kiln diff <left> <right> [--format FMT]
  • kiln demo --scripted [--seed N]
  • kiln inventory
  • kiln explain

Boundaries and drift

--edges replaces seeded records with boundary records: one all-minimum row, one all-maximum row, then one row per field where only that field is raised to its maximum. It does not use the seed or count, so the boundary suite never changes.

kiln check compares bytes, but a mismatch also prints a bounded, path-qualified report. JSON and JSONL changes are located as $.rows[0].id or lines[2]; CSV changes as rows[0].id. Added, removed and changed values are marked with +, - and ~. The report is computed in the pure core and never alters the verdict.

Manifest and review

A kiln.toml manifest gates every committed fixture in one command. It starts with version = 1, then one line per fixture: fixture = schema, fixture, format[, seeded|edges]. Entries run in declared order and the summary reports how many matched. The optional mode selects boundary generation instead of the seeded stream.

kiln diff compares two committed fixtures with the same structural differ used by check, so a review can see paths and values without regenerating anything. The format is inferred from the left file extension unless --format is supplied.

Fixture validation

kiln validate <fixture> --schema <schema> [--json] parses a hand-edited fixture and reports type and bound violations by path, for example rows[0].id. It covers JSON, JSONL and CSV and never regenerates the fixture: exit 0 means clean, 1 means issues found, 2 means the fixture could not be parsed.

Contract export

kiln export <schema> emits a draft-2020-12 JSON Schema describing one generated record: object properties from the declared fields, type and bounds per field, a required list and additionalProperties: false. It is a pure one-shot rendering; editors and validators can consume the result without knowing the Kiln DSL.

Schema introspection

kiln fields <schema> [--json] lists every field with its type, detail and bounds in declaration order. It is a one-shot pure transformation: no fixtures are generated and no state machine is needed.

Corpora

kiln corpus <schema> --seeds A..B --out-dir DIR [--format FMT] writes one deterministic fixture per seed, named <record>_<seed>.<ext>. The range is bounded to 1000 seeds. All renders are prepared in the pure core; an explicit write machine emits one write action per file so a failed write is never unaccounted for.

Machine-readable output

Add --json to check, diff or check --manifest to get one stable JSON object with "schema":1, a verdict and an ordered change list where relevant. Exit codes do not change, so the same command works for a terminal and for CI.

Architecture

The core is pure: schema reading, the seeded stream, generation, rendering, comparison, argument parsing and the state machine perform no I/O. The shell performs every file read, file write and print. The boundary is two data types: schema text enters, rendered bytes leave. Side effects are represented as actions emitted by the state machine and executed only at the edge.

Determinism

The same schema and seed produce the same bytes on every platform: one fixed xorshift64* stream, declaration-order fields, integer hundredths for decimals, and no hash-map iteration or clock reads. The check command turns that promise into a gate: it regenerates the fixture and compares bytes, normalizing line endings and trailing blank lines.
